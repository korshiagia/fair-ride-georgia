## Proposal status and shared envelope

Every endpoint/path/payload below is a **proposed behavior name**, not an existing API, OpenAPI implementation, executable command or authorized external call. External REST /v1 with stable enums and additive compatible evolution is the direction. In-process core coordination is not gRPC. Actual cross-process location/realtime/worker calls need workload TLS identity, bounded size, deadlines/cancellation and finite retries.

Command envelope fields: authenticated session/workload principal (server-derived), request_id, Idempotency-Key, operation_id, resource_id, expected_version(s), session_generation, assignment_generation or explicit NONE, policy_version, canonical payload. Actor/city/tenant header supplied by a client is a claim to validate, not authority. Server derives effective passenger/driver/fleet/corporate and booking_principal relationships, purpose and relevant city scope, then rechecks at commit and on replay. No personal ride visibility follows merely from employment/fleet membership.

All mutation rows inherit [global TR guard/recovery](trip-transition-catalogue.md#global-mutation-contract--applies-to-every-tr-row): PostgreSQL effect/result/outbox/audit transaction defines success; provider request accepted means only durable intent/attempt, not final money. Response includes request/command ID, authoritative resource version, assignment generation, policy/amendment references, permitted actions and independent trip/assignment/payment/safety state where authorized. 202 is only a durable accepted job/intent with query reference; queued client or socket delivery alone cannot return durable success.

Key scope = authenticated principal + operation + resource; canonical payload mismatch → IDEMPOTENCY_CONFLICT. Same key/payload returns same effect under **current access checks**; revoked principal cannot read cached original response. Store no plaintext PIN, PAN/CVV, tokens or raw identity/incident content in cached result. Seven-day response retention inherited from technical baseline is an UNVALIDATED-HYPOTHESIS; approved business/provider-reference uniqueness must outlive response-cache expiry. Unknown retention/replay windows must be resolved before use, not silently defaulted.

Bounded recovery proposal: at most three client retries with jitter within a 30-second overall command deadline, followed by original-key status/snapshot recovery. These numbers are engineering hypotheses for client/SRE/security review, **not accepted metrics or production configuration**. Provider UNKNOWN uses queried finality and owned reconciliation instead of that generic retry loop; exact bank windows/key lifetime remain unknown. Do not retry business/permission rejection or change payload/key after uncertainty.

## Errors, deadlines and degraded reads

Safe envelope example (synthetic documentation only): `error.code=ASSIGNMENT_STALE; request_id=req_example; retryable=false; current_trip_version=<authorized value>`. Stable codes map to localized ka/en messages; never include stack traces, other tenants, PSP secrets, exact route, identity scans or hidden risk scores.

| HTTP / code family | Deterministic meaning | Permitted response |
|---|---|---|
| 401 AUTH_REQUIRED | Invalid/expired session | Authenticate/recover; no effect |
| 403 ACCESS_DENIED or concealed 404 | Current relationship/purpose absent | Deny both first command and replay; no leaked resource metadata |
| 409 STATE_CONFLICT / ASSIGNMENT_STALE / ACTIVE_TRIP_EXISTS / IDEMPOTENCY_CONFLICT | Version, generation, active claim, quote binding or key/payload mismatch | Authorized snapshot/current trip or safe conflict; do not automatically submit a new mutation |
| 422 *_HOLD / EVIDENCE_INSUFFICIENT / PIN_INVALID | Business guard or required input fails | Show specific safe recovery; no default policy/fee/provider fallback |
| 429 RATE_LIMITED | Bounded quota/queue | Retry-After within approved overall deadline; avoid PIN/OTP lockout abuse |
| 503 SNAPSHOT_UNAVAILABLE / BACKPRESSURE | Authoritative/dependency capacity unavailable | Pending command query with original key; mark permitted stale read; no DB-less assignment/money success |

Read-only report pages may use authorized clearly stale projection; critical command consistency and snapshot recovery use owner authority, never replica eventual state as an acceptance guard. Pagination is opaque cursor plus bounded page-size under same tenant/purpose authorization; no cross-tenant enumeration. Numeric page/message/deadline caps remain pending measured review. Unsupported enum/action/version returns explicit compatible recovery or upgrade-needed message; old client cannot coerce a new policy state.

## Snapshot, events and recovery

OP-25 snapshot includes authoritative trip_version, attempt/assignment_generation, server_time, policy/quote/amendment versions, independent payment/safety-permitted status and next authorized actions. Reconnect first fetches snapshot, then subscribes using resource-authorized cursor. Duplicate/older versions ignored; gaps/refetch, membership removal/revocation and schema incompatibility force reauthorization/snapshot. Event cursor proves delivery position only.

Outbox event envelope: event_id, owner/event_type, schema_version, aggregate_id/type/version, city/service reference, occurred_at, correlation/causation; minimized payload references. Partition order only per aggregate/session, no total order across topics. Core mutation+outbox atomically; publish at least once. Consumer effect+inbox atomically before offset ack. Dedupe horizon covers replay; otherwise clean isolated projection rebuild and durable business reference uniqueness. Replay has external-effects-disabled mode; narrowly approved recovery authorizes any external job individually after status reconciliation.

Redis reconstructs hot indices/caches from approved authority and fresh session samples; it never recovers an old driver's availability from buffered history. Kafka outage permits bounded core outbox plus authorized snapshot fallback until capacity admission control; brokers/WebSockets are not durable command acknowledgments. No architecture or provider change is selected by an outage.
