## Global mutation contract — applies to every TR row

All proposed mutations require authenticated actor derived server-side; effective tenant/resource relationship at commit time; request ID, scoped idempotency key and canonical payload hash; expected aggregate version(s), current session generation, bound policy version and relevant assignment/attempt generation. Not-applicable assignment generation is explicit NONE (identity, prebooking, privacy, fleet/policy); it never removes the owning aggregate's version or session fence. Workers carry workload identity + authorized business intent and current relationship, not a captured unrestricted user role.

A normal success is the committed PostgreSQL owner/coordinator transaction: effect + new aggregate version + durable idempotency result + outbox + required restricted audit. Domain participants use in-process application interfaces. No response/event/socket/Redis/PSP acknowledgment substitutes for this commit. A read/hot-telemetry operation explicitly names its weaker boundary. Do not hold a DB transaction open over a provider call. No network service/database per domain is implied; gRPC only at actual workload process boundaries.

All rows reject missing inputs, wrong owner/tenant, illegal source state, expired/revoked eligibility, mismatched expected versions or stale generation **before effect**. Current-access recheck applies to idempotency replay too. Rejection produces stable safe localized error and no downstream effect. Serialization conflicts retry the whole bounded transaction with same intent; lock order is deterministic. Policy/evidence ordering uses authoritative server decision time, effective dates and monotonically advancing versions/generations, never device-clock-only freshness or Kafka cross-partition order.

**Universal uncertain command recovery:** response lost/timeout after possible commit means pending confirmation, not failure. Query authenticated owner snapshot and command result for original key; retry only same operation/key/payload within deadline. No new booking, charge, payout or refund key on uncertainty. Safe rejection returns current authorized version/actions or conceals resource existence. PSP attempts additionally remain UNKNOWN until authoritative query/reconciliation; missing query evidence blocks affected flow for owned manual exception. Consumer inbox dedupe and business-effect uniqueness survive short response-cache expiry. Event replay is projection-only and cannot rerun external side effects.

## Independent machines and ownership

Identity bootstrap exception: TR-01 first verifies a bounded, expiring server-issued OTP/recovery challenge under anti-enumeration and attempt controls; no existing bearer session is assumed for initial account verification. The challenge-bound principal/key/version fences that operation, and only verified challenge ownership may issue the new session. Session recovery/revocation and all other mutations use current authenticated authority. New-resource commands use explicit expected absence plus predecessor itinerary/quote/policy versions; read-only TR-25 has no mutation version precondition but returns authoritative versions.

- Trip: REQUESTED → SEARCHING → ASSIGNED → DRIVER_EN_ROUTE → DRIVER_ARRIVED → IN_PROGRESS → COMPLETED; permitted terminal alternatives NO_DRIVER/CANCELLED/ABORTED. Terminal facts immutable; append disputes/corrections.
- Assignment: NONE / RESERVED offer / COMMITTED / RELEASED, with explicit generation and unique active trip/driver/vehicle constraints. Lease expiry affects offer, never committed assignment.
- Payment: INTENT / AUTH_PENDING / AUTHORIZED / CAPTURE_PENDING / CAPTURED / SETTLEMENT_PENDING / SETTLED, with separate FAILED/UNKNOWN and refund/payout operations. UNKNOWN is not terminal failure; card hold is not revenue/cash. Cash reported and corporate debt are distinct.
- Safety: NONE / OPEN / OWNED / ESCALATED / CLOSED / APPEAL; risk restriction is its own reasoned versioned decision. Case does not rewrite trip/payment.
- Booking: DRAFT / SCHEDULED / CONFIRMED / READY / RESCHEDULED / CANCELLED / NO_SHOW; named buffered commitments are distinct from live assignment.

Reference boundaries: [domain owners](../../../DOMAIN-BOUNDARIES.md), [ADR-007](../../../adr/007-dispatch-and-trip-invariants.md), [ADR-008](../../../adr/008-fares-ledger-and-payments.md), [funds-flow F-01–09](../../legal/funds-flow.md). Entitlement at completion is unresolved accounting policy, not assumed capture. Every journal batch balances debit/credit in integer minor units per currency under immutable posting-rule version and unique effect reference; refunds/chargebacks/corrections append, never edit.

## Ordering and finance exceptions

TR-04 must claim both passenger active-immediate uniqueness and quote single-binding atomically, independent of key-based replay. Corporate booker is not automatically the passenger; do not globally relax uniqueness for delegated booking. TR-07 rechecks driver/vehicle membership, permit, shift, current reservation and future commitment feasibility while locking authority. Initially sequential live offers only; no speculative batch fanout.

TR-09 arrival evidence, passenger notification eligibility, grace/cap and fee decision are distinct facts. Notification intent alone cannot prove delivery rule satisfied. If approved notice/grace/quality policy is missing or failed/unknown, no automatic chargeable waiting/cancel/no-show penalty. Staff evidence exception may document arrival but cannot fabricate notice or waive a monetary eligibility guard.

TR-10 consumes PIN only in authorized start transaction; approved narrow exception records independent verifier, scoped reason and evidence, time, actor and later review, and keeps generation/version/exclusivity guards. Proposed attempt/expiry limits need security/product approval before use. No offline PIN bypass.

TR-13 durable capture intent precedes external call. BOG signed raw-body callback is the public design reference PP-B06; TBC callback alone is only a lookup trigger until verified status. Bind reference/merchant/amount/currency and action finality; reject mismatches, quarantine contradictions, query original attempt before any retry. PSP keys plus outbox/inbox and reconciliation reduce duplicates; **no end-to-end exactly-once money effect across DB/broker/PSP is claimed**.

TR-17 uses original payment refund cap (captures minus verified prior refunds and applicable dispute allocation), approved allocation among fare/tax/tip/promo/commission, separately funded customer obligation and distinct lawful recipient recovery. BOG PP-B05 says refund does not reverse completed/in-progress split transfer. Already paid driver/fleet receivable or merchant loss requires reviewed liability rule; no unexplained negative payout, cross-party debt netting or presumed custody from delayed payout.
