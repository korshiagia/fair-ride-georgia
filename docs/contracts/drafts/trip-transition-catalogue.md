## Global mutation contract — applies to every TR row

All proposed mutations use exactly one authority variant in the [finite authority matrix](#authority-matrix): challenge proof, current human session, or a currently authorized workload executing one versioned business intent. Each supplies request ID, scoped key, secret-safe payload fingerprint, owner expected versions, bound policy and relevant generation. Session/assignment NONE is an explicit typed absence justified by that variant; historical assignment references cannot authorize live driver actions. Current tenant/resource/purpose and human read/replay ACL always apply. Workload authority is not a captured user session and cannot become unrestricted delegation.

A normal success is the committed PostgreSQL owner/coordinator transaction: effect + new aggregate version + durable idempotency result + outbox + required restricted audit. Domain participants use in-process application interfaces. No response/event/socket/Redis/PSP acknowledgment substitutes for this commit. A read/hot-telemetry operation explicitly names its weaker boundary. Do not hold a DB transaction open over a provider call. No network service/database per domain is implied; gRPC only at actual workload process boundaries.

Every row rejects failed lifecycle/authority preconditions before its requested domain effect. Current human/session/workload permission, owner versions and applicable generation are rechecked, including replay. Optional fee entitlement, PIN attempt accounting and previously committed uncertain provider intents have separate outcomes explicitly specified below; a rejected start can commit restricted attempt evidence, and missing fee evidence cannot reject valid cancellation. Rejection never causes the rejected trip/money action. Stable localized error conceals unauthorized metadata. Serialization conflicts retry the whole bounded transaction with same intent; lock order is deterministic. Policy/evidence ordering uses authoritative server decision time, effective dates and monotonically advancing versions/generations, never device-clock-only freshness or Kafka cross-partition order.

**Universal uncertain command recovery:** response lost/timeout after possible commit means pending confirmation, not failure. Query authenticated owner snapshot and command result for original key; retry only same operation/key/payload within deadline. No new booking, charge, payout or refund key on uncertainty. Safe rejection returns current authorized version/actions or conceals resource existence. PSP attempts additionally remain UNKNOWN until authoritative query/reconciliation; missing query evidence blocks affected flow for owned manual exception. Consumer inbox dedupe and business-effect uniqueness survive short response-cache expiry. Event replay is projection-only and cannot rerun external side effects.

## Independent machines and ownership

Identity bootstrap exception: TR-01 first verifies a bounded, expiring server-issued OTP/recovery challenge under anti-enumeration and attempt controls; no existing bearer session is assumed for initial account verification. The challenge-bound principal/key/version fences that operation, and only verified challenge ownership may issue the new session. Session recovery/revocation and all other mutations use current authenticated authority. New-resource commands use explicit expected absence plus predecessor itinerary/quote/policy versions; read-only TR-25 has no mutation version precondition but returns authoritative versions.

- Trip: REQUESTED → SEARCHING → ASSIGNED → DRIVER_EN_ROUTE → DRIVER_ARRIVED → IN_PROGRESS → COMPLETED; permitted terminal alternatives NO_DRIVER/CANCELLED/ABORTED. Terminal facts immutable; append disputes/corrections.
- Assignment: NONE / RESERVED offer / COMMITTED / RELEASED, with explicit generation and unique active trip/driver/vehicle constraints. Lease expiry affects offer, never committed assignment.
- Payment: INTENT / AUTH_PENDING / AUTHORIZED / CAPTURE_PENDING / CAPTURED / SETTLEMENT_PENDING / SETTLED, with separate FAILED/UNKNOWN and refund/payout operations. UNKNOWN is not terminal failure; card hold is not revenue/cash. Cash reported and corporate debt are distinct.
- Safety: NONE / OPEN / OWNED / ESCALATED / CLOSED / APPEAL; risk restriction is its own reasoned versioned decision. Case does not rewrite trip/payment.
- Booking: DRAFT / SCHEDULED / CONFIRMED / READY / RESCHEDULED / CANCELLED / NO_SHOW; named buffered commitments are distinct from live assignment.

Reference boundaries: [domain owners](../../../DOMAIN-BOUNDARIES.md), [ADR-007](../../../adr/007-dispatch-and-trip-invariants.md), [ADR-008](../../../adr/008-fares-ledger-and-payments.md), [funds-flow F-01–09](../../legal/funds-flow.md). ## Ordering and finance exceptions

TR-04 must claim both passenger active-immediate uniqueness and quote single-binding atomically, independent of key-based replay. Corporate booker is not automatically the passenger; do not globally relax uniqueness for delegated booking. TR-07 rechecks driver/vehicle membership, permit, shift, current reservation and future commitment feasibility while locking authority. Initially sequential live offers only; no speculative batch fanout.

TR-09 arrival evidence, passenger notification eligibility, grace/cap and fee decision are distinct facts. Notification intent alone cannot prove delivery rule satisfied. If approved notice/grace/quality policy is missing or failed/unknown, no automatic chargeable waiting/cancel/no-show penalty. Staff evidence exception may document arrival but cannot fabricate notice or waive a monetary eligibility guard.

TR-10 consumes PIN only in authorized start transaction; approved narrow exception records independent verifier, scoped reason and evidence, time, actor and later review, and keeps generation/version/exclusivity guards. Proposed attempt/expiry limits need security/product approval before use. No offline PIN bypass.

TR-13 durable capture intent precedes external call. BOG signed raw-body callback is the public design reference PP-B06; TBC callback alone is only a lookup trigger until verified status. Bind reference/merchant/amount/currency and action finality; reject mismatches, quarantine contradictions, query original attempt before any retry. PSP keys plus outbox/inbox and reconciliation reduce duplicates; **no end-to-end exactly-once money effect across DB/broker/PSP is claimed**.

TR-17 uses original payment refund cap (captures minus verified prior refunds and applicable dispute allocation), approved allocation among fare/tax/tip/promo/commission, separately funded customer obligation and distinct lawful recipient recovery. BOG PP-B05 says refund does not reverse completed/in-progress split transfer. Already paid driver/fleet receivable or merchant loss requires reviewed liability rule; no unexplained negative payout, cross-party debt netting or presumed custody from delayed payout.

<a id="terminal-cleanup"></a>
## Terminal cleanup and fee independence — TR-05/06/12/18/19

The PG trip coordinator locks trip and deterministically ordered passenger/assignment/driver/vehicle/offer-reservation rows. It checks exact source state, trip_version, owner trip ID and applicable generation. One terminal winner writes immutable reason/end evidence, trip/assignment versions, command result, required audit/outbox and releases only claims whose owner=(this trip, this generation). Conditional release cannot clear a newer passenger or driver/vehicle claim, including a later trip after a retry. Retain assignment/offer/claim history and bound quote; terminal status never unbinds a quote for reuse.

TR-06 deadline with no valid winner commits NO_DRIVER and atomically invalidates its own outstanding offers/reservations and releases its passenger active-immediate claim. A competing valid accept wins only under the same locked state/generation check; losing expiry cannot release COMMITTED assignment. Retry after NO_DRIVER needs a new lawful unexpired quote and new booking intent/claim, even if old response was lost. Authorization hold reversal is a separate durable VOID/query intent; pending money never retains lifecycle claims.

TR-05 verified authorization failure creates a versioned fee-free TR-18 cancellation intent under the finite terminal-workload grant. While trip remains unstarted and owned, that coordinator commits CANCELLED and releases its own claims, even with no driver session or successful settlement. UNKNOWN stays REQUESTED/pending and cannot match; reconciliation queries original authorization before any retry or definitive failure/VOID. Late success on an already-cancelled trip never restarts dispatch; it schedules only lawful same-reference release/reconciliation. VOID UNKNOWN remains independent payment uncertainty.

TR-19 explicit approved abort locks IN_PROGRESS and current assignment_generation, serializes against completion, writes ABORTED/end evidence and releases its trip/passenger/driver/vehicle claims, marks assignment RELEASED and revokes its outstanding offers/reservations. Safety case stays open/owned under its own version; provisional fare is a distinct reviewed intent, not automatic completion/capture. Absent reviewed provisional-money policy leaves accounting HOLD without blocking an otherwise authorized ABORTED terminal release. Safe physical handling/staff ownership remains an external operational gate. An SOS/report, disconnect, stale GPS or lost heartbeat alone never terminates/releases.

TR-18 lifecycle validity is decided separately from optional fee entitlement. A permitted prestart cancellation commits CANCELLED/release even when quality, notice/grace, fee policy or funding evidence is absent. Response carries trip outcome CONFIRMED plus fee_decision=ZERO or REVIEW_PENDING (no automatic debit), with payment release/VOID status independently PENDING/UNKNOWN/CONFIRMED. FEE_EVIDENCE_HOLD labels only the optional fee decision. Illegal poststart cancel yields STATE_CONFLICT; only explicit abort may end it. Rematch releases old assignment/driver/vehicle claims and advances generation but retains the same passenger's active-trip claim.

<a id="scheduled-handoff"></a>
## Scheduled live handoff — TR-20 with TR-03/04/05/06

A versioned booking stores passenger, booking principal, exact service/jurisdictions, local+UTC trigger/check-in/deadline, separately accepted scheduled pricing/consent and future buffered commitments. It does not keep an immediate quote or payment hold silently valid until departure. At due trigger, the current booking workload rereads effective city/airport/directed-corridor/licence/category/driver-vehicle eligibility, actual passenger, current delegated corporate membership/spending and credit/budget rules. Unsupported automatic charging or guarantee stays HOLD.

Resolve pricing first: a still-valid expressly scheduled-binding quote/contract may be used within its exact validity; otherwise issue a fresh TR-03 quote and obtain current passenger/delegated consent or explicit scheduled-price amendment. Record predecessor scheduled-price/quote/consent and any accepted amendment version in the live fare snapshot; no expired immediate quote is extended, and an already trip-bound quote is never rebound. Expired immediate quote requires reconfirmation. Prepare the exact approved payment mode/coverage and required consent, not a second independent charge. The handoff transaction below persists the new mapped trip's payment intent; external authorization happens afterward through TR-05. Any still-valid expressly reusable scheduled authorization is linked once by original payment reference with approved scope/expiry/capture allocation; it is not recreated. Expired hold requires approved reauthorization, UNKNOWN remains owned pending, corporate budget is reserved atomically. Never imply scheduled consent licenses indefinite merchant-initiated charging.

One guarded PG handoff transaction locks booking/trigger/quote/passenger claim, dedupes booking_id + trigger_generation and enforces at most one current booking→live-trip mapping across trigger generations, checks current gates/versions and binds one quote to one new REQUESTED trip with its payment intent. It acquires the actual passenger's active-immediate claim exactly as TR-04 across distinct keys/devices, not the booker's. Before TR-06 SEARCHING, TR-05 confirms that mapped trip's current authorization/credit and TR-06 sets a fresh bounded matching deadline. If payment must occur after durable intent, REQUESTED holds the own passenger claim while pending, and definitively failed authorization follows fee-free terminal cleanup. An existing active trip, elapsed trigger window, missing consent/gate or commitment conflict yields booking HOLD/reconfirm/reschedule with no second live trip and no inferred no-show fee. Repeated trigger returns the mapped trip/pending reason; never creates a replacement while its outcome is unknown. Reschedule increments booking/trigger version and invalidates older trigger; a new generation cannot create another live trip while the prior mapped trip is nonterminal or uncertain. After terminal cleanup, only explicit reviewed reconfirmation with a new lawful quote/payment intent can create a new historical mapping, retaining predecessors. Future calendar commitment alone never becomes a live assignment; only TR-07 may acquire exclusive driver/vehicle claims.

<a id="pin-secret-envelope"></a>
## PIN verification and secret-safe replay — TR-10

Use separate purpose-bound keyed verifier and keyed request fingerprint with approved cryptographic key versions isolated from record/backup readers. A raw PIN or unkeyed hash of PIN plus predictable trip fields must never be retained as canonical payload. The transient canonicalization binds exact operation/trip/assignment/challenge_version, approved nonsecret fields and PIN using a secret-key MAC; persistent records keep only fingerprint/key_version and minimal outcome. Keys are segregated, access-audited and rotation/verification windows reviewed; backup cannot carry a standalone offline PIN oracle. PIN attempt/challenge retention and finite per-challenge/account/driver/device rate and expiry limits are UNSET until security review; absent approved limits disables PIN issue/start rather than unlimited guesses.

Under one PG lock, check current challenge_version, trip/assignment/version, expiry, one-use state and authoritative attempt/rate counters. Invalid attempts atomically increment the durable bound even with different keys/concurrent guesses; Redis throttling is supplemental. Same-key different fingerprint gives IDEMPOTENCY_CONFLICT and cannot reset attempts; new keys cannot bypass bound counters. A rejected PIN start has no trip effect but persists minimized attempt/result evidence. Valid start atomically consumes verifier, commits IN_PROGRESS/start, advances versions and stores nonsecret idempotent result. Concurrent starts/reissue serialize: reissue advances challenge_version/revokes prior verifier; consumed/old challenge cannot start again. Original successful-key result lookup under current authority returns start proof without resubmitting consumed PIN or counting another guess. After a definite rejected attempt, a new corrected proof uses a new attempt key within unchanged counters, never after uncertain success without status lookup. No plaintext PIN in queue/log/events/errors/crash/session replay/cache/backups; protected transient display/input only.

<a id="amendment-funding"></a>
## Amendment consent and funding choreography — TR-11/13

Separate immutable proposal/consent from effective amendment. Approved exact delta/currency/version remains CONSENTED_PENDING_FUNDING until payment coverage and current corporate spending authority are confirmed; original accepted fare/service stays effective. Coverage within a valid approved authorization may proceed only under reviewed capture rules. An increase above card authorization requires a provider-supported, company-approved incremental authorization or replacement reauthorization with explicit customer consent and a reviewed old-hold release/capture plan. Bind one amendment/payment operation and stable provider reference before calling outside PG. No assumption that public preauth documentation establishes merchant incremental/MIT capability.

Replacement must prevent old and new authorizations being independently captured for the same service; retain supersession/allocation references and approved maximum total capture. Provider UNKNOWN queries/reconciles that original operation before retry, blocks effective increase and does not silently create a second key/charge. Absent provider capability/funding gives AMENDMENT_FUNDING_HOLD; definite refusal preserves original terms or permits an explicitly consented and policy-approved alternative funding/termination/dispute. No hidden cash switch or extra paid service before funded effective approval. Corporate delta atomically reserves additional approved budget/credit at current membership/version or fails without spend. On funding confirmation the PG coordinator rechecks trip, amendment, consent, payment coverage and current spending versions; only then records EFFECTIVE delta/new fare/outbox once. A competing stale/aborted trip never activates a late funded proposal: reconcile/release unused authorization under original operation. Partial capture/VOID/refund liability and expiry remain external merchant/finance gates.

## Beneficiary and economic-time precedence — TR-07/14/21

TR-07 stores driver/vehicle/fleet eligibility at assignment and the candidate beneficiary agreement/version; this alone is not earned entitlement. At the approved economic earning event, snapshot event_id/time, agreement_id/version, party_id, allocation/currency, effective relation record and posting-rule version. Select the legally reviewed agreement effective at that event; only an explicit reviewed agreement rule may carry the assignment-time beneficiary forward. Thus precedence is reviewed service-specific agreement + its earning-time/effective selection, then immutable economic snapshot; current fleet membership is solely an access/eligibility fact.

Transfer midtrip cannot silently reroute earnings to a new manager/party. Missing/overlapping earning rule or agreement means ACCOUNTING_HOLD for entitlement/payout; terminal trip release still succeeds. Future relationship/contract changes apply prospectively, not by rewriting a historical payable. Lawful correction appends an audited balanced adjustment with original economic snapshot/reference and approved maker/checker basis; never net unrelated parties' debt. Payout uses original approved party and bank mandate, with current finance workload/approval authority, not a current driver's session or fleet-history visibility. Exact earning instant/allocation and transfer rule remain F-07/08 professional/company gates.
