## Reading and interaction contract

Stable IDs are never recycled. Each Screen row links both its Transition and Operation; each linked row returns here. Acceptance IDs below are proposed expected outcomes, never test results. [Policy](city-policy-schema.md), [data map](../../security/drafts/privacy-data-map.md) and [threat register](../../security/drafts/threat-model.md) add the same ID links. These latter files are produced in subsequent tasks of this plan.

State tuple is always trip / assignment / payment / safety (plus booking where relevant). Show each independently; unavailable values say pending or unknown, not success. Global degradation: preserve last **confirmed** version with staleness, queue only permitted protected intents, display mutation as pending until durable core confirmation, then use [OP-25](api-behavior.md#op-25). Read-only history never authorizes a pending action. Offline identity, PIN or finance input cannot establish success.

All surfaces support Georgian and English text; stable error codes are separate from translated messages. Accessible names, logical focus/status announcements, scalable text, keyboard and screen-reader navigation, non-color states, manual address/text alternatives to map gestures, and equivalent consent/cancel/appeal controls are proposed acceptance obligations. Preserve entered safe draft when a session expires; never cache PIN/payment/incident contents for convenience. Hardware/background, accessibility and real language validation remain NOT RUN.

## Full journey and service overlays

Proposed personal card flow: SCR-01 → SCR-02 → SCR-03 → SCR-04 → SCR-05 → SCR-06 → SCR-07 → SCR-08 → SCR-09 → SCR-10 → SCR-11 if consented → SCR-12 → SCR-13 → SCR-15 → SCR-16 → SCR-17. SCR-14 replaces the collection/credit path for approved cash/corporate service; completion never proves card settlement, commission collection or beneficiary payout. SCR-18 and SCR-19 are guarded alternative paths; SCR-25/26 apply throughout.

Fleet uses SCR-21 + SCR-14 with effective contract and beneficiary snapshot; corporate uses SCR-22 + business versions of SCR-03/04/14/15, never the employee's personal history. Scheduled/airport/intercity use SCR-20, independent policy and calendar commitments before actual trip matching; future bookings do not monopolize the active assignment. Airport variants have meeting point, pickup/dropoff, flight-delay/check-in, notice, no-show and replacement/refund status; corridor variants retain directional origin/destination/traversed jurisdictions, category, deadhead and safe-stop uncertainty. Missing permission or capability shows disabled/HOLD, not an airport guarantee.
